Admin Panels — Setup & Testing Guide

A walkthrough for running the Admin Panel and Super Admin Panel on your own computer, so you can click around and test everything yourself.

1

Backend

The engine room. Runs once in the background and feeds real data to both panels.

2

Admin Panel

Day-to-day staff console — users, posts, challenges, badges, analytics.

3

Super Admin Panel

Everything above, plus device fleet management and staff roles.

Before you start

What you'll need installed

Node.js is already on your machine. Three more free tools are needed — install these once and you're set for good.

✓

Node.js — already installed

Nothing to do here.

1

Python

Powers the backend. Download from python.org — during install, tick the box that says "Add Python to PATH."

2

Firebase CLI

Stands in for a real Firebase project on your computer, so no account or billing is needed. Open a terminal (see the tip below) and run:

Command Prompt
npm install -g firebase-tools
3

Java (JRE)

Only needed because the Firebase emulator itself runs on it. Download from adoptium.net (choose the latest LTS version). Skip this if Java is already on your machine for something else.

How to open a terminal in a folder: open the folder in File Explorer, click into the address bar at the top, type cmd, and press Enter. A black Command Prompt window opens, already pointed at that folder.

Step 1

Download the project

1

Get the code

Go to the project page and click the green Code button, then Download ZIP. Once downloaded, extract/unzip it somewhere easy to find, like your Desktop.

Inside the unzipped folder you'll see four folders: strola_health_backend_fastApi, strola_health_admin_next, strola_health_super_admin_next, and strola_health_flutter. You only need the first three for this guide.

Step 2 — do this once each time you test

Start the backend

Both panels show real data only while this is running. Leave its terminal window open the whole time you're testing.

1

Start the local Firestore/Auth emulator

Open a terminal inside strola_health_backend_fastApi and run:

Command Prompt
firebase emulators:start --only firestore,auth

The first run downloads some files (takes a minute). When ready, you'll see a table confirming it's listening. Leave this window open and open a new terminal window for the next step.

2

Set up the backend (first time only)

In a new terminal, inside strola_health_backend_fastApi:

Command Prompt
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env

Then open the new .env file in Notepad and fill in just these three lines (everything else can stay blank):

.env
FIRESTORE_EMULATOR_HOST=localhost:8080
FIREBASE_AUTH_EMULATOR_HOST=localhost:9099
FIREBASE_PROJECT_ID=strolla-health-dev
3

Load sample data (first time only)

With the emulator from step 1 still running, in the same terminal:

Command Prompt
python scripts/seed_emulator.py

This fills the panels with realistic sample users, posts, devices, and challenges to click through — see the login details further down.

4

Start the backend itself

Command Prompt
uvicorn app.main:app --reload

Leave this running too. You now have two terminal windows open (emulator + backend) and both should stay open while you test.

Bonus — want to peek behind the curtain? With the backend running, open http://localhost:8000/docs in your browser. That's the live, interactive API reference (Swagger UI) — every action either panel can take, listed out, with a "Try it" button on each one.
the backend above must stay running for either panel below to work

Step 3

Run the Admin Panel

1

Open a new terminal

Inside strola_health_admin_next, run:

Command Prompt
npm install
copy .env.local.example .env.local
npm run dev
2

Open it in your browser

Go to http://localhost:3100 and log in with one of the accounts below.

Step 4

Run the Super Admin Panel

1

Open a new terminal

Inside strola_health_super_admin_next, run:

Command Prompt
npm install
copy .env.local.example .env.local
npm run dev
2

Open it in your browser

Go to http://localhost:3200 and log in with the super admin account below.

You can run both panels at the same time — they use different addresses (3100 and 3200), so just keep both terminal windows open alongside the backend ones.

If something goes wrong

Troubleshooting

"Address already in use" when starting something — another program on your computer is already using that port. Close other terminal windows from a previous attempt and try again.
Panel loads but every page shows an error — almost always means the backend or emulator terminal windows aren't running anymore. Check both are still open without errors.
Nothing happens when you type a command — make sure the terminal is open inside the right folder (the prompt should show the folder name).
Lost the login details? Re-run python scripts/seed_emulator.py — it's safe to run again any time and refills the same sample data.
