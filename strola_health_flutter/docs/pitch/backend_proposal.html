strolla health
Technical Proposal · Part 1 of the Platform Roadmap

The app is ready.
Now it needs a backend.

Strolla Health today is a beautifully finished Flutter app with live BLE step tracking, GPS workouts, community, challenges and sharing — but almost everything social and historical runs on placeholder data that lives only on one phone. This document shows exactly what a Python backend unlocks, and how we deliver it in safe, demo-able phases.

01
Where we are today

Everything lives — and dies — on one phone

The hardware pipeline is real and works well. But there is no server: nothing is backed up, nothing is shared between users, and every social feature is a façade rendered from hard-coded data inside the app.

What this means for launch
  • Two users installing the app see identical fake friends and posts — trust is broken on day one
  • A lost or replaced phone wipes the user's entire history
  • Marketing cannot run challenges, referral or retention campaigns
  • No analytics: we can't see usage, retention or device health
The good news
The hard part — a polished, feature-complete frontend — is already done. The app was architected with clean repository layers that are explicitly "backend-ready". We swap mock repositories for API calls; screens don't change.

05
Delivery plan

Three phases — each one independently demo-able

We never disappear for months. Every phase ends with a working build in your hands.

Phase 1 — Foundation
  • Accounts: sign-up, login, password reset
  • Onboarding profile stored server-side
  • Step & workout sync (offline-first queue)
  • Real weekly/monthly stats from real data
  • API documentation delivered
Demo: log in on two phones — same data on both.
Phase 2 — Social Core
  • Real community feed: posts, likes, comments
  • Friends: search, connect, block, report
  • Public profiles with privacy controls
  • Share-to-community goes live
  • Content moderation tools
Demo: two real users interacting in the feed.
Phase 3 — Engagement
  • Challenges: join, create, invite, live leaderboards
  • Achievement engine & real PR detection
  • Push notifications (likes, goals, reminders)
  • Real notification inbox
  • Admin dashboard: users, content, metrics
Demo: a live challenge between the whole team.
The bottom line
Strolla Health has a launch-quality frontend wrapped around placeholder data. A focused 12-week Python backend turns every screen real, protects user data, and unlocks the community features the entire product is designed around. Without it, the app cannot honestly go to market.
